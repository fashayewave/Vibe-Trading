# HQATL Project Roadmap

## Purpose

This roadmap defines the long-term development path for Hew's Quant Analytics Trading Lab (HQATL). It translates the approved HQATL Vision into a sequence of governed project stages while preserving research discipline, validation requirements, explainability, and human decision authority.

This document is a project roadmap only. Detailed analytical rules, technical specifications, implementation designs, and validation procedures belong in their respective approved documents.

## Governing Document

The governing scope for this roadmap is [00_HQATL_VISION.md](00_HQATL_VISION.md). The ten divisions in that document define the intended long-term capability areas of HQATL.

## Current Status

HQATL is in the foundation stage. The project vision has been recorded, the existing repository has been reviewed at an architectural level, and the initial governance-document structure has been established.

Current work is focused on defining scope, preserving existing capabilities, recording decisions, organizing research, and establishing approval gates before implementation begins.

No roadmap item should be interpreted as implemented functionality unless executable code and relevant tests have been separately audited.

## Current Era

**Foundation**

The Foundation era establishes the project identity, architectural boundaries, governance records, research standards, terminology, preservation constraints, and phased development plan.

## Current Stage

**Architecture, Discovery, and Governance Documentation**

The current stage is documenting what exists, what is planned, what requires research, and what must receive approval before later development phases begin.

## Next Milestone

**Foundation Documentation Baseline Complete**

The next milestone is to complete and review the initial Decision Log, Feature Audit, Research Library, and HQATL Glossary so that the Foundation era has a consistent, traceable, and approval-ready documentation baseline.

Milestone completion requires:

- The governing documents to use consistent terminology and status vocabulary.
- Existing capabilities to be distinguished from planned or prompt-only capabilities.
- Open decisions and research questions to be recorded rather than assumed.
- Preservation constraints and phase boundaries to be documented.
- Human approval to be recorded before progression to the next phase.

## Roadmap Governance

- The approved Vision controls the long-term scope of this roadmap.
- The Decision Log records approved choices and rejected alternatives.
- The Feature Audit records evidence about existing capabilities.
- The Research Library records sources, claims, conflicts, and validation needs.
- The HQATL Glossary controls shared terminology.
- Roadmap status does not establish implementation status.
- Each phase must stop at its defined approval gate.
- No live execution capability is authorized by this roadmap.

## Specification Gatekeeping Workflow

All future HQATL capabilities must follow the locked governance sequence:

Research Library
↓

Research Review Queue
↓

Evidence Review
↓

Verified Evidence Library
↓

Research Specification
↓

Architecture Design
↓

Engineering Specification
↓

Implementation
↓

Testing
↓

Validation
↓

Production Candidate

Each transition is a gate. Registration is not approval, testing is not validation, and production-candidate status requires final human review.

## Roadmap Review

This roadmap should be reviewed when:

- A foundation document is approved or materially revised.
- A development phase reaches its completion gate.
- New evidence changes project priorities or scope.
- A planned capability is approved, rejected, implemented, or tested.
- A preservation constraint or architectural boundary changes.
